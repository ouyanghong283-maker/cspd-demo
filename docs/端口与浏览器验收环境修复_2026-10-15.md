## 路径选择

| 路径                                                        | 优点                                         | 代价及风险                                   | 选择                                   |
| ----------------------------------------------------------- | -------------------------------------------- | -------------------------------------------- | -------------------------------------- |
| 沿用现有 Chrome、Angular 与 MCP，统一地址并补齐自动验收入口 | 改动集中，使用现有依赖，可留下实际浏览器证据 | 仍依赖执行环境允许监听端口及启动 Chrome      | 采用                                   |
| 重装或更换浏览器                                            | 适用于缺文件、缺库或损坏                     | 已有浏览器可以启动，不能解决环境拒绝系统调用 | 不采用                                 |
| 迁移远程浏览器或部署平台                                    | 可换到具备所需权限的执行环境                 | 增加部署、网络和配置维护；当前无此必要       | 保留为确实再次遇到环境限制时的后续选择 |

## 已实施

1. `scripts/browser-config.mjs` 统一既有脚本默认地址为 `http://127.0.0.1:4200`，保留 `CSPD_BASE_URL` 覆盖并处理末尾斜杠。
2. 新增 `npm run acceptance:browser`。默认选择空闲端口、启动本仓库 Angular 服务、等待 HTTP 就绪并确认返回 CSPD 页面。启动与浏览器调用有等待上限。独立服务禁用文件监听、热更新与自动重载，使验收使用启动时编译的版本。
3. 通过 MCP 的 `--isolated` 使用临时浏览器配置，验收数据不会进入日常演示配置。只停止本次启动的 Angular 进程；指定既有服务时不停止该服务。
4. 验证主页面、模块入口及详情路由，使用真实 MCP 点击、填写和保存客户，刷新后核对稳定客户编号与名称，记录控制台及网络错误并输出截图。
5. MCP 客户端持续读取子进程 stderr 并保留末尾诊断，避免输出管道积满；本地库路径保留已有 `LD_LIBRARY_PATH`。
6. 每次运行独立保存 `results.json`、`server.log`、`mcp.log`、网络及控制台日志与截图。失败返回非零退出码。

## 使用方法

在 `my demo` 文件夹运行：

```bash
npm run acceptance:browser
```

命令打印本次服务地址和证据目录。默认服务在验收结束后关闭。日常人工验收继续使用：

```bash
npm start -- --host 127.0.0.1 --port 4200
```

然后在 Windows 或 Linux 浏览器打开 <http://127.0.0.1:4200/>。

验收现有服务时，在 Linux/WSL 使用：

```bash
CSPD_BASE_URL=http://127.0.0.1:4200 npm run acceptance:browser
```

PowerShell 使用：

```powershell
$env:CSPD_BASE_URL='http://127.0.0.1:4200'
npm run acceptance:browser
```

如再出现 `listen EPERM`、`setsockopt` 或 `shutdown: Operation not permitted`，先保留本次运行日志并检查执行环境权限。调整端口号或重装浏览器无法消除禁止监听或禁止系统调用的策略。若提示浏览器文件缺失，运行 `npm run browser:install`，或通过 `CHROME_PATH` 指向可用 Chrome。

# CSPD 业务操作前端 DEMO

Angular 22 演示应用，覆盖客户与线索、商机推进、项目计划、启动交底、验收和内部移交。提供 13 个角色、34 条操作路径与连续业务接力。Minimalism 风格，使用本地中文字体和 SVG 图标。

2026-10-12完整性复核：主线动作可到达移交接收，但仍有任务状态、资料重验、数据复用和独立上手缺口，尚未达到全部需求验收。详见[最新全过程复核](docs/功能完整性与全过程复核_2026-10-12.md)。

## Windows 使用者先看这里

完整图文指南：[下载并解压仓库](https://github.com/ouyanghong283-maker/cspd-demo/archive/refs/heads/main.zip)后，双击 `引导/Windows本地使用指南.html`。含下载安装、启动、角色练习与报错排查。也可先阅读 [Windows 使用说明](Windows使用说明.md)。

建议 Node.js 24 LTS（至少 24.15.0），无需安装 Git、Python、数据库或全局 Angular。

## 启动

**使用者（推荐）**：仓库已附带构建好的页面，无需 `npm ci`。装好 Node.js 后，Windows 双击 `启动DEMO.bat`、macOS 双击 `启动DEMO.command`，浏览器会自动打开 demo；端口被占用时自动换用下一个。也可在命令行运行 `node serve-demo.js` 达到同样效果。

**开发者**：需要 Node.js 22.22.3 以上的受支持版本（本环境使用 26.11.1）。

```bash
# 在 package.json 所在文件夹打开命令窗口
npm ci
npm start -- --host 127.0.0.1 --port 4200
```

先在右上角选择角色，再进入「演示控制与指南」选择案例或「去练习」。切换角色和案例保留修改；重置需要确认。

V4快速演示：销售登记线索 → 模拟需求导入表转商机 → 补齐意向沟通并进入方案报价 → 创建内部报价草稿 → 方案角色交付V1 → 销售确认质保与服务协议并保存报价条件 → 财务在草稿阶段确认税费 → 销售提交、主管模拟审核 → 记录发出与客户接受 → 主管最终锁定 → 记录洽谈与合同谈判沟通、赢单并关联项目 → PM模拟BOM留档 → 财务加载模拟快照、回款与最终实际成本。报价条件影响税费时需在发出前重新确认；已发报价仅保留历史，不能补改税费。WBS、SAT、客户验收和移交继续沿原页面操作。

关键交底、SAT、客户验收或移交资料修改后，页面分别显示待复核事项，对应任务不再计为已完成。按各自入口重新确认；移交资料变化后由PM重新提交、接收方再次确认，原审核、签认和接收历史保留。

重点投标使用 DEMO-O002，交底缺件使用 DEMO-P002，验收使用 DEMO-P006，待接收使用 DEMO-P007。每页提示当前应做的操作和缺失项；表单可「填入演示内容」。V4附件全部为可编辑文件名的模拟元数据，不保存、预览或下载原件。旧附件仅显示旧记录；更正通过新记录或新版本。

## 实现与演示范围

Standalone 组件、OnPush、Signals/computed、按路由懒加载和 Reactive Forms。业务规则集中在 `src/app/core/`；V4业务记录与模拟附件元数据保存在 localStorage；旧版本IndexedDB原件不再读取，确认整套恢复时一并清理。附件关联、业务状态、历史和站内模拟通知同步更新；刷新可继续操作。

初始样例包含 12 个客户、12 条线索、24 个商机、6 份合同和 8 个项目，含不同国家、币种、等级、阶段、30/60 天冷却、同合同多项目、缺件、退回、验收与接收等情形。金额不跨币种相加。

审批、合同/G3、生产和账务为就近标注的模拟结果。单浏览器操作，无真实系统接口、跨设备协作或生产权限认证。PM 会议原文件没有讨论正文，相关流程沿用原 PRD，供业务走查确认。税费展示固定案例与待确认备注；预测权重、冷却阈值及模板为演示假设。

原环境没有安装名为 uiux 的技能，已使用可用的 frontend-design 技能落实用户要求的 minimalism 视觉风格。

所有既有浏览器脚本统一默认连接 `http://127.0.0.1:4200`，先运行 `npm start -- --host 127.0.0.1 --port 4200`；通过 `CSPD_BASE_URL` 可指定其他地址。既有业务验收脚本会修改或重置演示数据，运行时请指定独立的 `CSPD_MCP_PROFILE`。旧数据迁移保留ID，不会把旧附件自动当作已交付方案或已确认服务；从「演示控制」确认恢复可获得完整V4示例。

推荐先运行 `npm run acceptance:browser`：无需手动启动服务，自动选择空闲端口，检查 HTTP、Chrome、页面路由、真实表单保存和刷新，并保存桌面与窄屏截图。每次均使用自动清理的临时浏览器配置，不读取日常演示数据。结果和日志保存在 `artifacts/browser-environment/<本次运行编号>/`，失败返回非零退出码。若需要验收已经启动的服务，在 Linux/WSL 使用 `CSPD_BASE_URL=http://127.0.0.1:4200 npm run acceptance:browser`，在 PowerShell 先执行 `$env:CSPD_BASE_URL='http://127.0.0.1:4200'` 再运行命令。指定现有服务时仍使用临时浏览器，且不会停止该服务。

此入口只确认浏览器验收环境可用，不能代替完整业务验收。原先 EPERM 和 Chrome 权限错误的记录、处理路径与本次证据见[端口与浏览器验收环境修复记录](docs/端口与浏览器验收环境修复_2026-10-15.md)。

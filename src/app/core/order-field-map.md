# 订单与订单明细字段来源映射

`order-field-map.json` 按字段来源附件逐项记录标准CRM系统（Dynamics）的订单和订单明细字段，包括源实体/逻辑名、原始分类、拟定本地对象与路径、维护归属、编辑规则、CSPD 必填原文、枚举/关联线索、来源文件和源行号；主表单定位另记录定位 CSV 的行号。它是可追溯的字段清单，不声明字段已经进入业务页面或 Store。

## 来源口径

- 全量字段及拟定去向：`doc/PRD/DEMO PRD/V7PRD/附件/01_标准CRM全量字段去向.csv`
- 主表单字段定位：`doc/PRD/DEMO PRD/V7PRD/附件/02_当前主表单字段定位.csv`
- 实体计数说明：`doc/PRD/DEMO PRD/V7PRD/附件/README.md`

README 与全量字段 CSV 一致：源逻辑实体 `salesorder`（订单）308 字段，`salesorderdetail`（订单产品/明细）220 字段，合计 528 条。此次以 CSV 的 `CRM实体逻辑名` 为准。需求文本里的 `alp_salesorder` / `alp_salesorderdetail` 并不是来源 CSV 中的实体逻辑名；本地承载建议使用 `SalesOrder` 与 `SalesOrderLine` 的字段路径仍照来源原文保留，不把本地对象名倒推为远端实体名。

原始来源分类仍逐字段保留，并另归并为三类：`业务字段`、`业务状态` → `business`；`只读业务字段`、`派生/伴随字段` → `readOnly`；`系统字段`、`本地主键/来源标识` → `technical`。来源中的CSPD必填处理保存在 `sourceCspdRequiredHandling`；当前展示值 `cspdRequiredHandling` 将笼统的“CRM红星”明确为“标准CRM系统红星”，避免与项目内非标CRM混淆。其他拟定路径、字段必填、字典、关联、编辑规则和证据文件依来源原文保存，未知和待核内容不作推断。

`reviewFlags` 只标记来源中明确出现的未决文案（映射规则待核、运行时必填证据未取得、字典未决或 CSPD 必填待核）；未决原文同时保留。空标记不代表已实现或已核实。专项测试逐行对照 01/02 两份 CSV，验证精确字段覆盖、类别、映射、原文待核标记和行号。

README 写主表单字段数为订单122、订单明细113；02 定位 CSV 实际有订单125行/121个唯一逻辑字段、订单明细114行/113个唯一字段。该清单忠实保留 02 中每个源定位行（包括重复行），未自行调和 README 与定位 CSV 对订单主表单数量的差异。
